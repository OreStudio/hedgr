#+title: Hedgr
#+description: A multi-instance ImGui client for OreStudio.

Hedgr is a multi-instance desktop client for OreStudio over NATS. It holds many
instances at once, each with its own accounts and sessions, and draws each
session's work in its own floating window.

There is no per-window marker option and no notion of "the" instance. One Hedgr
process holds the whole set, so there is nothing to tell apart.

* Layout

Hedgr follows the OreStudio component conventions. Each component is a
single-module component: a CMake root that adds =src=, =tests= and =modeling=,
with =include/<component>/= holding one folder per facet.

| Component         | Holds                                                       |
|-------------------+-------------------------------------------------------------|
| =hedgr.model=     | Value types, live state tables, commands and events.        |
| =hedgr.store=     | The SQLite schema and its repositories.                     |
| =hedgr.session=   | The blocking NATS transport and the IAM login round trip.   |
| =hedgr.runtime=   | The thread pool, the session workers and the state owner.   |
| =hedgr.ui=        | ImGui and ImPlot rendering, icons and theme.                |
| =hedgr.imgui=     | The executable: the GLFW window, the frame loop, the wiring. |

Dependencies run one way only. =hedgr.model= depends on nothing else in Hedgr,
and =hedgr.ui= does not depend on =hedgr.runtime=: the interface reads the state
tables and pushes commands, and the runtime applies them.

* Building

Hedgr consumes a pre-built OreStudio: its headers come from the OreStudio
source tree and its shared libraries from an OreStudio build output.

#+begin_src sh
build/scripts/build.sh                    # configure and build everything
build/scripts/build-target.sh hedgr.ui.lib  # one target, no reconfigure
#+end_src

The release build lands in =build/output/linux-clang-release/publish/=.

* Packaging and deployment

The publish directory is the deployable artefact. The build copies OreStudio's
shared libraries into =publish/lib= and rewrites their RUNPATH, so the tree
runs from wherever it is unpacked. Copying the files is not enough: a bundled
library that keeps an absolute RUNPATH resolves its own dependencies through
that path and fails even with the file beside it.

#+begin_src sh
build/scripts/build-target.sh package_hedgr      # publish/ -> hedgr-<ver>.tar.gz
build/scripts/deploy.sh                          # package, copy, unpack, verify
HEDGR_DEPLOY_HOST=goedel HEDGR_DEPLOY_DIR=hedgr build/scripts/deploy.sh
#+end_src

The host keeps one directory per version and a =current= symlink, so a deploy
never overwrites a running version. The smoke test runs =--version=, which the
argument parser answers without opening a window, and it proves the bundle is
complete because the loader resolves every library before =main= runs.

=patchelf= is required to build the package.

* Running

The environment supplies the connection settings; Hedgr reads the =ORES_HEDGR_*=
variables and never persists a credential. It starts fullscreen; F11 toggles.

#+begin_src sh
build/scripts/run.sh
#+end_src

A Wayland session needs its display named explicitly when the variable is not
already exported:

#+begin_src sh
export WAYLAND_DISPLAY=wayland-0
build/scripts/run.sh
#+end_src

Mesa prints EGL warnings about a missing driver on a machine with no GPU. They
are not fatal, and the run still produces a frame.

To check a change without a person watching, ask for one frame; the process
writes frame eight and leaves.

#+begin_src sh
HEDGR_CAPTURE=$PWD/.cache/verify/frame.ppm build/scripts/run.sh
#+end_src

* Adding a window kind

Three places, and the compiler checks two of them:

1. a new alternative in =model::domain::window_state= and a new enumerator in
   =model::domain::window_kind=;
2. a renderer in the table in =hedgr.ui/src/render/renderer.cpp=, which is a
   =constexpr std::array= indexed by kind, so a missing entry fails to compile;
3. an entry in the Instance Manager's open-window action.
